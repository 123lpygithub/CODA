# Privacy · deepseek-1 · 方法与限度

本版覆盖 652 个 artifact，形成 11 个主题代码与 1948 条 artifact–code 成员关系。

## 实际执行的方法

1. 从 `dataset/personal_data_protection_github/source/extracted/coded_issue_data.csv` 选取 `is_privacy_related == true` 的 652 条 issue，并从 `source/github_snapshot_20261106_v10/issues/*.json` 拼接正文、评论和发布元数据，冻结为 652 个 artifact。
2. 按 artifact 顺序分批完整阅读全部可用文本，包括长讨论、粘贴代码、日志、后续更正与反驳；逐条记录开放代码、分析备忘录、结果与证据可用性。
3. 阅读完成后把开放代码归并为 11 个主题代码，保留多标签、反例和争议，不把参与者法律主张、`closed` 状态或合并 PR 改写成已验证事实。
4. 对 19 条部分证据条目逐条重读冻结正文与评论；证据只覆盖标题/元数据时仅支持标题可见的议题，无法定位具体机制的条目才使用 PRIVACY-Z，不由匹配关键词补出内容。
5. 对每条证据在当前冻结 `content` 中重新定位并计算字符偏移；不沿用其他结果包的坐标。

## 编码原则

- 分析单位与去重口径见 `codebook.json` 的 `unit`；同文重复不合并。
- 一个 artifact 可多标签；多标签只表示材料支持多个独立机制，不表示因果排序。
- 类别定义、纳入/排除和边界示例先于成员检查固定；遇到相邻案例时回到定义比较，而不是按关键词投票。
- 负例、证据不足和未决状态被保留；没有为了覆盖率强行给出具体机制。
- 证据必须是冻结 `content` 的逐字子串；证据片段不等于完整语境，完整原文见 `artifacts.jsonl`。

## 材料边界与解释限制

- 652 条来自适配器选出的隐私相关 issue，不是上游全部 issue；抓取快照是 2026-11-06 的当前可获取版本，不是原论文历史时点的完整复现。
- 633 条完整、19 条部分证据；所有本地可用文本已逐条阅读。外部网页、图片、视频、附件和链接 PR 内容未获取，不计为已阅读。
- 标题/元数据、作者陈述、法律解释、安全承诺和“无 PII”主张都保留其来源地位，不自动升级为已验证事实。
- 代码表示材料涉及的主题，不代表风险成立、措施实施或问题已解决；结果字段单独记录完成状态。
- 本版是一个 AI 编码者的质性分析，没有独立人工双编码、访谈、饱和度实验或编码者一致性统计；结构校验不能替代这些质量控制。

## 与旧结果的关系

本版以既有 Privacy 决策底稿为起点，逐条对照冻结 issue 正文与评论复核，并修正反例归属与高标签边界；旧标签没有被当作自动规则。
