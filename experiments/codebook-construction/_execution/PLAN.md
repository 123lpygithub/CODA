## 研究问题与材料范围

- SATD：开发者在 ML 软件中表达哪些技术债务问题？856 个发布案例，使用完整原注释、可恢复源码、多位置候选和版本说明。
- Privacy：这些 issue 中提出哪些个人数据问题，现有证据显示它们如何被处理？652 个发布案例，使用正文、全部已恢复评论、历史补充、完整已下载的关联文本及来源限制。
- 从 v10 冻结快照及对应原始缓存构造输入。不读人工 taxonomy、参考编码列、论文结果、CodeErrors 类别，也不提供 GitHub harmonized labels 等可能造成分类锚定的字段。
- 同一内容在不同源字段完全重复时只读一次，并保存来源别名；不是截断。超长文本分段覆盖全部字符，保留字段与偏移量。不可获取的材料明确标为缺口，不用人工标签补写。

## 每次运行的方法

| 步骤 | 操作 | 验收 |
|---|---|---|
| 1 冻结输入 | 保存全部原文、来源、状态、散列与顺序 | 856 / 652 个唯一 ID，无人工类别字段 |
| 2 开放阅读 | 每个 artifact 的全部文本分段进入独立调用，提取现象、证据与不确定性；没有 codebook | 每个分段均有保存且校验的响应，引用必须为原文子串 |
| 3 逐例归纳 | 仅合并同一 artifact 各段观察；保留矛盾、时间和证据限制 | 每条都有具体观察，不用关键词规则自动定类 |
| 4 分组归纳 | 按文本预算分组比较现象，生成暂定概念与范围，不预设数量 | 组内每个 artifact 被列为支持案例 |
| 5 全局整合 | 比较暂定概念，递归合并同义与可共享定义的概念，保留必要边界 | 所有前一层暂定概念均有映射，没有丢弃来源 |
| 6 全量分配 | 用本轮最终候选定义重新编码每条；每项有独立证据 | 所有 ID 有分配，引用在原文存在，类别引用有效 |
| 7 修订 | 无合适类别时提出缺口，整合后全量重分配，最多 3 次实质修订 | 不为完成率强制归类；耗尽则保留未完成候选与原因，不标完成 |
| 8 导出核查 | 导出 codebook、分配、HOW 树、过程记录和覆盖审计 | 全量覆盖、每类有支持、多标签不重复、原文证据一致 |

类别归纳追求可复用且有边界的概念，不为每个 issue/函数建单独类别，也不强制与人工类别数量相同。多标签仅表达不同的、有证据的现象。

## 两次运行的隔离

两次从相同证据开始、用同一研究问题和方法。仅材料顺序不同（固定随机种子 6101 与 6102）。每个 API 请求显式构造 messages，不复用聊天线程、上一轮摘要、类别、分配或其他结果。两个输出目录与缓存完全隔离。共享的只有原始材料和方法说明。

不用同一助手在看过第一份结果后凭记忆改写第二份来冒充独立构建。两次独立请求也不等于两个独立的人类编码员或统计独立样本，不刻意制造差异。
